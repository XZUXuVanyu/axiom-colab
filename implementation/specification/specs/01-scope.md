# 01 产品范围与用户决定

REQ-01 全部自主业务为 C++20，Windows 11 x64 为 V1 目标；Visual Studio 2022 的 CMake 打开与 F5 调试是正式开发入口。已有更高 VS 版本可并存，但必须使用冻结的工具集并记录；不静默更换 ABI。

REQ-02 完整流程：建立目标→审核设计→普通 C++ 项目双向协作→不可变候选→独立验证→用户批准精确包→长期库发布→新工作区绑定→组合实验→封存证据→交付可独立运行的物理声音产品。每一步有真实状态与来源。

REQ-03 外部 coding agent 从上下文生成 src，用户可在 VS 逐行调试；用户也可先写框架，agent 只修改批准区域。V1 不重写编辑器，不嵌入付费模型路由。

REQ-04 一个用户级工具库与多个独立工作区。工具是版本化能力；工作区是项目数据、目标与运行边界。库发布不自动授权调用，删除工作区不删除已发布包。

REQ-05 Qt 节点画布具有添加/删除/移动/连线/断线/参数编辑/保存/载入/运行/取消/查看结果/封装一层组合。执行采用冻结快照、串行 DAG；支持分叉汇合。拒绝环，失败下游 skipped。没有自动运行、跨 run 缓存、并行调度、任意深度组合。

REQ-06 同一个纯 C++ 拨弦 DSP 用于离线 Tool、JUCE Standalone 和通用 Windows x64 VST3。GUI 必须可调物理参数并试听；VST3 以同一个包面向 Ableton Live 和 FL Studio。若仅实测一个宿主，仅声明该宿主通过，完整双宿主目标仍未关闭。Max 不是自动降级选项。

REQ-07 原子工具类有类型端口、参数、权限、资源与模型假设描述。黑箱可进入源码检查和调试。组合包只封装数据流，不隐藏权限。

REQ-08 科学信息有单位、语义、数值策略、来源与验证状态；核心维持共同契约，算法可通过版本包替换。V1 实现所需最小元数据与拨弦内核，不实现通用符号代数、通用误差传播、通用 PDE/积分引擎。

REQ-09 硬件会话、强实时控制和三维模型编辑作为后续能力。V1 预留有版本类型与能力枚举并拒绝 unsupported，不能做空实现却宣称支持。计算内核和工程状态不依赖二维 UI 类型。

REQ-10 原生产 main 保存 legacy 后用正常提交建立新版内容。课程仓库保持原状。此提示包生成不代表远端已迁移。

## 明确不做

云服务、多租户、远程硬件、通用 LLM API、自动科研结论、无需用户的自动发布、实时图编译、GPU 计算后端、3D 编辑器、任意 DLL 热加载、移动端、Linux 必需环境、多声部合成、混响采样库、Max 适配。不能用这些扩展替代 V1 中尚未完成的功能。

## 执行域

实验域处理整段数据，允许进程隔离和落盘；音频域在 DAW/Standalone 内固定时间预算运行原生 DSP；未来设备域使用长期会话及本地控制器。三者共享版本与来源概念，不共享一种任意节点调度器。
